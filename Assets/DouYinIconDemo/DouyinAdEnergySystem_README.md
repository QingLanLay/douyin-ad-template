## 一键切换本地无广告链接（noAds）

在场景 `DouyinAdSystem` 的 `AdManager` 上勾选 **No Ads（字段 `noAds`）**，保存场景后重新运行或使用普通 Unity WebGL 构建。默认关闭，不改变现有抖音渠道模式；无需修改调用方的 `TTSaveManager` 或领奖接口。

- **优先级**：`noAds` 高于 `isTest`、SDK 初始化、测试广告界面、插屏保护期与冷却。激励仍保留入口，每次调用只执行一次原成功回调；插屏立即执行继续/关闭回调。
- **SDK 插屏包装**：`TTSDK.TTInterstitialAdWrapper` 位于 SDK 的 WebGL 程序集内，内部统一判断 `noAds`。项目的 Android/WebGL 与 iOS 插屏创建和展示已接入此包装；无广告时不执行创建/展示委托，直接完成继续回调且不记真实展示。外部新增插屏也应使用包装入口，不直接绕过调用原厂 `TTInterstitialAd.Show()`；原厂 DLL 不作二进制修改。
- **体力领取**：无广告模式的普通体力按钮点击即发放 `adRewardEnergy`（默认 +5，不超过 `maxEnergy` 默认 10）并保存；无限体力仍保持原规则，完成两次点击领取后激活，不新增等待或测试广告。
- **本地存档**：Int / Float / String / Bool 使用 `UnityEngine.PlayerPrefs`，保持 key 和默认值；`SetJson` / `SetJsonArray` 使用 `Application.persistentDataPath/noads-local.json`，按原 `Save()` 时机持久化。普通 WebGL 会额外把文件同步至浏览器 IndexedDB。暂停、失焦和退出时补保存。
- **损坏保护**：本地 JSON 保留 `.bak`，读取损坏数据时返回备份或默认值，不自动覆盖损坏原件。后续显式保存会把损坏原件保留为 `.corrupt`。
- **显隐**：自动隐藏添加桌面、侧边栏、分享、排行榜按钮及侧边栏面板，保留体力、宝箱和其他激励业务 UI。可通过 `noAdsHideObjects` 指定额外抖音专用预制体；不要填入玩法/体力或管理器自身。场景 Inspector 切换支持显隐预览及撤销；取消勾选仅恢复切换前状态，不强行显示原本关闭的面板。
- **平台能力**：不调用 SDK 初始化、登录、平台文件系统、推荐流订阅/就绪、排行榜、震动和巨量上报。分享/侧边栏/加桌不伪造成功、不自动发平台奖励。
- **模式隔离**：不读取或覆盖抖音 SDK 存档，也不自动迁移抖音线上数据；清空无广告存档只清理由该兼容层登记的本地 key 和本地 JSON，不删除其他系统的 PlayerPrefs。
- **发布**：使用 `File > Build Settings > WebGL > Build`（本项目已使用默认 WebGL 模板），部署到 HTTP(S) 服务器；不要使用抖音 SDK 导出器。这是保留 SDK 资产的双模式开关，不是彻底删除 SDK 的迁移，也不会自动上传/生成公网地址。SDK 专用入口在无广告模式隐藏，取消开关可恢复抖音模式。


## isTest 广告生命周期模拟（2026-10-26）

- 测试模式不再立即返回广告成功：改用常驻系统内预先放置的激励/插屏广告预制体，模拟初始化、加载、展示、关闭和失败。
- 激励广告提供“一键看完”，跳过倒计时后仍需关闭才回调发奖；提前关闭或模拟失败不发奖。
- 测试和真实模式共用启动 30 秒保护、插屏 60 秒间隔与全屏互斥；测试广告结束后恢复游戏/音频原状态。
- `noAds` 仍保持最高优先级，不受本次测试模式改动影响。详细使用及模拟边界见 `ADSScripts/AdTest/README.md`。

## 每日按钮红点（2026-10-26）

- 红点美术通过 `image25-ui-api` 的 `gpt-image-2.5` 生成，透明 PNG 已包含简洁描边、阴影和高光；4 个按钮使用同一图片资源，但红点仍是各按钮下各自独立的场景子物体。
- **场景位置联动**：在非 Play 的编辑状态，直接选择任一按钮下的 `DailyRedDot`，修改 RectTransform 的 Pos X / Pos Y（或拖动位置），同场景其余红点自动同步到各自按钮下的相同相对坐标，包含未激活的按钮。只记录场景实例修改，不应用或修改按钮预制体，也不创建公共红点预制体；保存场景即可保留调整。显隐状态和单独尺寸不参与同步。

- 添加侧边栏、分享、添加桌面、排行榜 4 个原子按钮的右下角均带有固定的 `DailyRedDot` 子物体，可直接在场景实例或预制体中调整位置、大小和颜色，不在运行时创建。
- 每个按钮独立记录本地自然日（`yyyy-MM-dd`）的点击状态。当天未点击时显示红点，点击对应按钮立即消失，不依赖分享、加桌或排行榜等业务结果。
- 点击日期通过现有 `TTSaveManager` 保存；当天退出重进、切换场景或重新打开面板不会恢复已点击按钮的红点。次日重新进入、回到前台或持续在线跨过午夜时会自动重新显示。
- 红点不改变原按钮显示、侧边栏每日领奖规则或平台 API；添加桌面仍在按钮点击的同步用户手势调用链内执行。

## 导入注意事项

1. 建议先备份目标项目。
2. 如果目标项目已经安装了更新版本的 ByteGame SDK 或 UniTask，请在 Unity 的导入窗口中取消勾选：
   - `Assets/Plugins/ByteGame`
   - `Assets/UniTask`
3. 将 `Assets/DouYinIconDemo/Prefabs/Systems/DouyinAdSystem.prefab` 放入首个启动场景一次。
4. 在 `DouyinAdSystem` 上填写目标应用自己的激励广告位、插屏广告位和推荐流 content_id。
5. 发布前关闭 `AdManager.isTest`；包内保留模板当前的测试模式，避免导入后误请求真实广告。
6. 原子按钮可以直接放到任意 Canvas。体力状态入口会查找当前已加载场景中的 `EnergyPanelView`，体力面板可以放在同一场景的任意 Canvas 下。
7. `SiderBarPanel.prefab` 可以直接放到任意 Canvas。`02_侧边栏.prefab` 点击后只激活该面板，不会直接调用平台 API；真正的侧边栏 API 仅由面板内部的“进入侧边栏”按钮调用。侧边栏奖励按本地自然日记录，每天最多领取一次。
8. `01_添加桌面.prefab` 和 `02_侧边栏.prefab` 不会再根据已添加或已领取状态隐藏自身；业务层可通过各自的 UnityEvent 显示提示。
9. 推荐流源码位于 `Assets/DouYinIconDemo/推荐流通用接入包`。导入后先阅读其中的 `README.md`，
   保证目标项目只有一个 `TT.InitSDK` 和一个 Feed 监听所有者，再填写
   `Resources/FeedRecommendationConfig.asset` 中的 ContentID 或远程 JSON 地址。

## 广告请求规则

- 抖音插屏在本次运行前 30 秒内禁止展示。
- 创建、加载、调用 `Show()`、`OnError` 或 `Show` 异常均不重置插屏 CD；TTSDK 没有 `OnShow`，只有收到 `OnClose`、确认插屏确实展示并关闭后，才开始本次运行内的 60 秒插屏 CD。
- 任意激励广告关闭后，本次运行内 60 秒不得展示插屏；该间隔不限制激励广告。
- 插屏间隔使用 `Time.realtimeSinceStartup` 保存在进程内，不写入 PlayerPrefs 或游戏存档。
- 插屏实例未创建或未加载完成时只创建/加载，不消耗 60 秒间隔。
- 插屏 `OnError` 或 `Show` 异常后会清理当前实例并停止自动申请；只有业务下次主动调用插屏接口时才重新申请一次。
- 激励广告按钮不得因为请求处理中而锁定；后一次点击替换旧业务回调并再次请求。
- 激励奖励只在 SDK 返回完整观看时发放，并通过请求编号隔离过期回调和重复奖励。
