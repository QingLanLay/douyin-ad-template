# isTest 广告生命周期模拟

## 使用

- 使用 `Prefabs/Systems/DouyinAdSystem.prefab` 中已挂好的测试系统。`noAds = false`、`isTest = true` 时启用；`noAds` 保持最高优先级，仍为激励直接成功、插屏立即继续。
- `Prefabs/AdTest/激励广告测试.prefab` 和 `插屏广告测试.prefab` 是独立、可编辑的预制体，并已作为常驻系统的固定子对象放置。不使用 `Resources.Load`、运行时 `Instantiate` 或临时生成 UI。
- 首次启动异步模拟 SDK 初始化（默认 0.1 秒），再创建/加载广告（默认 0.5 秒）。未就绪的激励请求走失败回调；加载/展示失败后由下一次主动请求重试，不自动循环重试。

## 激励视频

1. 就绪后点击业务激励入口，显示测试广告，模拟全屏互斥与游戏/音频暂停。
2. 默认播放 15 秒，使用非缩放时间；应用进入后台期间不累计观看进度。
3. “一键看完”立即跳过剩余时间，标记完整观看，**不会直接发奖**。
4. 看完后点击“关闭并领取奖励”，才触发 `onComplete`；提前“关闭广告”触发 `onFailed`，不发奖。
5. “模拟广告失败”触发错误/失败回调，不发奖。重复关闭/完成不会重复回调或发奖，并发请求不会覆盖当前广告的业务回调。
6. 看完和提前关闭都会重置插屏间隔；加载/展示错误不重置该间隔。

## 插屏

- 与真实模式共用本次运行启动 30 秒保护、全屏广告 60 秒间隔，不在测试模式绕过限制。
- 就绪且满足条件时显示测试插屏，点击关闭才触发 `onClose`。被保护期、冷却、并发、未加载或错误拦截时不伪造关闭回调，与当前真实分支保持一致。
- 关闭后重新预加载。错误后停止自动重试，等下次主动请求。

## Inspector 可调项

- `AdTestSimulator`：模拟初始化时长、是否暂停游戏/音频、`onAdShown` / `onAdClosed` 业务通知。
- 每个 `AdTestPanel`：加载时长、观看时长、下一次加载失败/下一次展示失败，以及已序列化的 UI 引用。
- 所有按钮的事件均直接保存到预制体。一键看完按钮连接 `AdTestPanel.CompleteImmediately`。
- 关闭或错误后恢复展示前的 `Time.timeScale` / `AudioListener.pause` 原值，不把原本已暂停的游戏错误恢复为运行。

## 模拟边界

这是项目层的广告生命周期模拟，不是抖音原生广告或操作系统生命周期。`onAdShown/onAdClosed` 用于模拟广告前后台业务通知，不伪造 Unity 引擎的 `Application.isFocused`、系统原生 OnHide/OnShow、真实用户手势权限、广告库存、计费或平台审核行为。

`isTest` 的 AdManagerImpl 路径使用本地日志模拟 SDK/登录/激活/广告收益/资源上报等，不发起真实平台请求；推荐流本身的卡片启动/复访调试仍使用现有推荐流调试工具，本功能不伪造完整平台 Feed 会话。

发布真实广告包前关闭 `isTest`。真实开发者工具/真机的 SDK、前后台行为与广告加载仍需单独验证。

## 编辑期维护

菜单 `抖音 → 测试广告 → 创建或更新生命周期预制体` 可重新生成默认 UI，**会重置两个独立测试广告预制体的布局**；手工改过 UI 后不要重复执行。正常使用无需运行菜单，直接编辑已有预制体。
## 本次验证（2026-10-26）

- 主工程 Unity 2022.3.62f1c1 已完成编译；后台 PlayMode 定向检查 25 项通过、0 项失败。覆盖预加载、一键看完后关闭发奖一次、提前关闭、并发、加载/展示错误与主动重试、暂停状态恢复，以及插屏启动保护和冷却。
- 启动 30 秒保护通过真实运行等待检查；60 秒间隔通过仅修改运行内时间戳的定向检查，不是等待完整 60 秒的真机验收。
- 两个预制体均以 1080×1920 在隔离预览场景渲染检查。新增专用 TMP 字体由项目同一份 DouyinSansBold.otf 预烘焙，未修改其他界面共用字体。
- 抖音开发者工具、真实设备、原生 SDK/操作系统生命周期、Unity 6000 和 WebGL 构建均未在本次验证。
- 早期后台探针因 Editor 未持续执行 PlayerLoop 出现等待超时；启用仅限探针的后台 PlayerLoop 推进后重新完成全部检查，未为探针修改项目运行参数。结果记录位于项目 `.artifacts/ad-test-lifecycle/runtime-probe-background.txt`。

## 场景手动测试按钮

- 示例场景 `Assets/Scenes/SampleScene.unity` 的 `AdsCanvas/AdsPanel/广告手动测试面板` 已直接放置“激励广告测试”和“插屏广告测试”两个按钮，UI 和 Button.onClick 都保存在场景中，可在 Inspector 自由修改。
- 面板显示当前 `noAds` / `isTest` 和激励成功、失败、插屏继续的计数。测试激励只统计回调，不给体力、不改存档；体力领取仍用原体力面板。
- `noAds=true` 时两个按钮保留，激励立即成功，插屏立即继续。`noAds=false,isTest=true` 时走模拟广告界面，插屏仍遵守启动 30 秒及全屏广告间隔 60 秒。
