# 推荐流抖音播放器 v1.0.22

## 运行方式

`FeedPlaybackController.UnityAudio` 继续实现共享的 `IAudio` 接口。抖音容器中，`TTAudioManager.CanUseNativeAudio()` 为真时使用 `FeedDouyinAudio` 与 `TTAudioManager.CreateInnerAudioContext`；能力不可用时使用包内公开 `tt.createInnerAudioContext`。Editor 和普通浏览器保留 AudioSource。

原生实现将本次编码音频写入用户目录，手机使用 SDK 的 USER_DATA_PATH，桌面开发者工具使用 ttfile://user。文件写入地址与音源 src 一致；支持 WAV、MP3、M4A、AAC，本地可读取 PCM 的 AudioClip 转为 WAV 后绑定。

## 生命周期

1. 首画面准备与 7001 由共享控制器处理，准备本身不播放配音。
2. 本会话有效的 OnShow 请求保留至内容和音源可用；AudioId 尚未返回时继续等待。
3. OnHide 取消待播请求或暂停同一音源，字幕保持隐藏。再次显示后等待当前显示期间新返回的播放位置。
4. 同一音源的播放、暂停、缓冲、结束事件及属性结果决定字幕状态。属性读取兼容标量和包含 id、value 的对象，拒绝其他音源与旧回调。
5. FeedEnter 停止卡片配音字幕。错误通过 AudioObservation.Error 进入错误页面；取消与释放注销事件、销毁音源并删除临时文件。创建前已取消的音源由管理器持续清理。

字幕继续使用 FeedSubtitle.prefab 的源关系与专用材质，在 FeedPlayback.prefab 中保留嵌套实例。

## 可复用文件

两个资源包由各自编辑器实际导出，已加入 unity-douyin-template-import 的包库并成为对应家族的默认版本。推荐流与配音字幕 Skill 已更新播放器选择和生命周期规则。

配音字幕 Skill 随附 `scripts/FeedPlayback/Test-FeedAudio.ps1`，传入目标工程的 ProjectPath 即可运行 SDK、控制器及两种音频接口测试；运行环境需要 PowerShell 7、.NET 9 SDK 和 Node.js。测试读取目标工程当前源码，报告保存在该工程的 .artifacts/FeedAudioTests。
